# ДЗ 3. Случайные величины и распределения (ИТМО)

Домашнее задание к лекции и семинару 3. Студент выполняет ноутбук в Google Colab, скачивает `.ipynb` и присылает преподавателю, а GitHub Actions проверяет ноутбуки автоматически.

| Файл | Что это |
|---|---|
| `hw03-random-variables-itmo.ipynb` | шаблон задания для студентов |
| `grader/grade.py` | автопроверка: запускает ноутбук с нуля и сверяет ответы |
| `grader/requirements.txt` | зависимости проверки |
| `submissions/` | сюда кладутся присланные ноутбуки |
| `../../.github/workflows/grade-hw03.yml` | workflow, который запускает проверку |

## Что в задании

5 задач по 2 балла, всего 10. У каждого студента свой вариант (1–40): от варианта зависят ряд распределения, плотность, данные и параметры задач, поэтому ответы у всех разные.

| Задача | Тема | Что проверяется |
|---|---|---|
| 1 | Дискретная величина | ряд распределения; своя функция `cdf_discrete` на случайных тестах; $P(1<X\le3)$ и $P(1\le X\le3)$ |
| 2 | Непрерывная величина $f(x)=cx^k$ на $[0;b]$ | константа, функция распределения `F2` (в том числе вне отрезка), вероятность, медиана |
| 3 | Генерация методом обратной функции | `sample_task2` — критерий Колмогорова; `sample_discrete` — частоты на 200 000 значений |
| 4 | Распределения в данных | оценка $\lambda$ Пуассона, вероятность перегрузки, квантиль показательного; опознать 3 распределения по выборкам |
| 5 | Монте-Карло | точная вероятность $P(\max(T_1,\dots,T_m)>t)$ и её оценка симуляцией |

Текстовый «Вывод» в конце автоматически не оценивается; по нему удобно задавать вопросы на защите.

## Как сдают студенты

Инструкция есть в первой ячейке шаблона:

1. Загрузить шаблон в Colab («Файл → Загрузить блокнот»), вписать ФИО, группу и номер варианта.
2. Заполнить `...` и `# TODO`, не переименовывая переменные.
3. «Среда выполнения → Перезапустить сеанс и выполнить все»; ячейка «Самопроверка» должна показать, что все ответы на месте.
4. «Файл → Скачать → Скачать .ipynb», назвать `hw03_Фамилия_Имя.ipynb` и отправить преподавателю.

## Как проверяет преподаватель

1. Положить присланные файлы в `homework/hw03/submissions/` и сделать commit и push.
2. Открыть вкладку **Actions → «Проверка ДЗ 3»** в репозитории. В отчёте запуска (Summary) появится таблица баллов по задачам и замечания по каждому студенту: какие пункты не прошли и почему, какие ячейки упали с ошибкой.
3. В разделе **Artifacts** того же запуска лежит архив `hw03-grades` с `grades.csv` (для ведомости) и подробным JSON по каждому ноутбуку.

Проверку можно запустить и вручную: **Actions → «Проверка ДЗ 3» → Run workflow**. Каждый запуск проверяет все ноутбуки в папке заново.

Локально, без GitHub:

```bash
pip install -r homework/hw03/grader/requirements.txt
python homework/hw03/grader/grade.py папка_с_ноутбуками --out grades
```

> [!warning] Репозиторий публичный
> Ноутбуки в `submissions/` и отчёт проверки с ФИО и баллами увидит любой, у кого есть доступ к репозиторию. Для реальной сдачи лучше завести **приватный** репозиторий и скопировать в него папку `homework/hw03/` и файл `.github/workflows/grade-hw03.yml` — больше ничего не нужно. Либо проверять локально командой выше.

## Как устроена проверка

- Каждый ноутбук выполняется с нуля в чистом ядре Python (как «Выполнить все»). Ошибка в одной ячейке не останавливает остальные, поэтому задачи оцениваются независимо.
- После всех ячеек студента в том же ядре запускается проверка: она читает `VARIANT`, сама пересчитывает правильные ответы варианта и сравнивает с переменными студента. Функции (`cdf_discrete`, `F2`, `sample_task2`, `sample_discrete`) вызываются на скрытых тестах, а не только на данных варианта.
- Лимит — 3 минуты на ячейку. Workflow работает без секретов и только с правом чтения, потому что выполняет чужой код.
- Ноутбук без номера варианта получает 0 с пояснением в отчёте.

**Ограничения.** Код проверки лежит в репозитории, так что студент теоретически может его прочитать. Ответы в нём не записаны, они вычисляются по варианту, поэтому прочитав проверку, студент узнает только *что* проверяется. Требование «в задаче 3 только `rng.random`» автоматически не проверяется — это вопрос для защиты.

## Если поменяли задание

Функции варианта (`params`, `make_data`) записаны в двух местах: в ячейке «Параметры варианта» шаблона и в `grader/grade.py` между метками `SHARED`. Если правите их в шаблоне, сделайте ту же правку в грейдере, иначе правильные ответы разойдутся.
